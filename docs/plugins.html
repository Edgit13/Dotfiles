Plugins

A folder
and a manifest

A plugin is plain QML. It can add a surface, a bar module, or both. There is no build step and no sandbox — it runs inside the shell, so only enable code you trust.

Where plugins live

~/.config/edots/plugins/<id>/plugin.json
~/.config/edots/plugins/<id>/<surface>.qml

# bundled examples
~/.config/quickshell/bar/plugins/<id>/
edots plugin              # installed plugins and their state
edots plugin folder       # open the user plugin folder
edots plugin path         # print it
edots plugin reload       # rescan folders
edots plugin enable world-clock
edots plugin open world-clock

Installed plugins and their enabled state are recorded in quickshell/plugins.json. Bundled examples can be copied into the user folder and edited freely.

Manifest

This is the real manifest of the bundled world-clock plugin. Every key except id is optional in practice, but a name, a version and at least one of surface / bar make it useful.

{
  "id": "world-clock",
  "name": "World Clock",
  "description": "Local time plus a few cities. Also available as a compact bar module.",
  "version": "1.0.0",
  "author": "Edots",
  "icon": "public",
  "defaultEnabled": false,
  "surface": {
    "qml": "WorldClock.qml",
    "width": 520,
    "height": 460,
    "end": true,
    "typing": false
  },
  "bar": {
    "qml": "WorldClockBar.qml",
    "position": "trailing"
  }
}

Fields

FieldMeaning
idFolder name and CLI handle. Keep it stable.
surface.qmlComponent opened as a floating surface.
surface.width, heightInitial size in logical pixels.
surface.endClose the surface when focus is lost.
surface.typingKeep the surface open while the keyboard is used.
bar.qmlComponent placed in the bar.
bar.positionleading, center or trailing.
iconMaterial Symbols name, used in lists and the bar.

Writing one

Start from the bundled example and reload:

cp -r ~/.config/quickshell/bar/plugins/world-clock \
      ~/.config/edots/plugins/my-plugin
$EDITOR ~/.config/edots/plugins/my-plugin/plugin.json
edots plugin reload
edots plugin open my-plugin

A plugin QML file is a normal Item. It can use the shell's theme singletons, services and controls because it is loaded by the same Quickshell process. Keep the surface self-contained and cheap to create — it is instantiated when opened.

Safety: plugins have the same access as the shell itself. There is no signing and no registry yet, so read the QML before enabling something from a stranger.
